# PROJECT_HANDOFF.md — Planly

Текущее состояние проекта на конец сессии. Это самый свежий статус-документ — читать в начале
новой сессии, до `docs/ARCHITECTURE.md`/`docs/MODULES.md` (те карты навигации сейчас частично
устарели, см. «Незавершённые задачи» ниже).

---

## 1. Что такое Planly сейчас

Персональный AI-планировщик. Монорепо на npm workspaces: `frontend/` (Next.js 16 + React 19 +
TypeScript + Tailwind v4), `backend/` (Express 5 + TypeScript + Postgres через `pg`, без ORM),
`database/` (SQL-миграции).

Профиль, задачи и события календаря живут в облаке через собственный API; `localStorage` для них
теперь только кэш. Остальные модули по-прежнему на `localStorage` и/или локальном `useState` (см.
таблицу ниже). Авторизация своя: email + пароль, сессия подписанным токеном в httpOnly-куке.
Реального AI нет.

Supabase удалён целиком — см. §3. Прежние миграции лежат в `database/legacy-supabase/` только для
справки и переноса данных.

## 2. Статус разделов

| Раздел | Маршрут | Данные | Статус |
|---|---|---|---|
| Dashboard | `/` | `useTasksStore` → API `/api/tasks` (+ `localStorage` как кэш) | Полностью рабочий |
| Calendar | `/calendar` | `useCalendarStore` → API `/api/calendar-events` (+ кэш) | Полностью рабочий |
| Projects | `/projects` | локальный `useState` + mock, **без** `localStorage` | UI-скелет, интерактивный |
| Notes | `/notes` | локальный `useState` + mock, **без** `localStorage` | UI-скелет, интерактивный (редактор, чек-листы, вложения) |
| Reminders | `/reminders` | локальный `useState` + mock (даты относительно реального `now`), **без** `localStorage` | UI-скелет, интерактивный (группировка, snooze, модалка создания) |
| Analytics | `/analytics` | mock-данные, масштabируемые по периоду | UI-скелет, интерактивный (графики на SVG, без библиотек) |
| Settings | `/settings` | `useState` (draft/saved) + **`localStorage` (`planly:settings`)** | Полностью рабочий: 12 категорий, save/cancel/reset, восстановление после reload |

Все 8 маршрутов используют общий `Sidebar` (`components/layout/Sidebar.tsx`) и `Header`
(`components/dashboard/Header.tsx`, принимает `title`/`enableTaskSearch` для не-Dashboard страниц).

## 3. Последние изменения (эта сессия, по порядку)

0. **Свой бэкенд вместо Supabase** (последняя сессия — крупнее всего остального ниже).
   Репозиторий стал монорепо: прежний Next.js уехал в `frontend/`, добавились `backend/` и
   `database/`. Бэкенд повторяет архитектуру DormHub: `routes → controllers → services →
   repositories`, валидация Zod, `AppError` + общий `errorHandler`, конфиг через Zod-схему env,
   лимиты запросов, заголовки безопасности, Dockerfile под Railway. Авторизация своя:
   пароли на встроенном `scrypt`, сессия — HMAC-подписанный токен в httpOnly-куке,
   подтверждение почты и сброс пароля через одноразовые токены в `auth_tokens`.
   На фронтенде `lib/supabase/*` заменён на `lib/api-client.ts`; `useAuth`, `useProfileStore`,
   `tasks-repository`, `useCalendarStore` и `proxy.ts` переписаны под API. Календарь впервые
   стал облачным (раньше только `localStorage`). Подробности — [docs/BACKEND.md](docs/BACKEND.md)
   и [database/README.md](database/README.md).
1. **Projects** (`/projects`) — сетка/список карточек проектов, статистика, боковая панель с
   мини-календарём и ближайшими задачами (переиспользует `useCalendarStore`/`useTasksStore` для
   чтения), архивный блок. Новые файлы: `types/project.ts`, `lib/projects-mock-data.ts`,
   `components/projects/*`, `components/ui/ComingSoonDialog.tsx` (общая заглушка-модалка,
   переиспользуется всеми последующими разделами).
2. **Заметки** (`/notes`) — список заметок с фильтрами по папкам/тегам, богатый редактор
   (секции, чек-листы, вложения, связи с проектом/задачей/событием). Sidebar расширен
   необязательным пропом `notesExtras` (панель папок/тегов рендерится только на `/notes`).
   Новые файлы: `types/note.ts`, `lib/notes-mock-data.ts`, `components/notes/*`.
3. **Напоминания** (`/reminders`) — группировка по времени (Просроченные/Сегодня/Завтра/На
   неделе/Позже), список и режим «Расписание», меню «Отложить» с реальным пересчётом
   даты/времени, мини-календарь с точками. Sidebar расширен `remindersExtras` (аналогично Notes).
   Новые файлы: `types/reminder.ts`, `lib/reminders-mock-data.ts`, `lib/reminders.ts`,
   `components/reminders/*`. Побочный фикс: в `Sidebar.tsx` класс `-left-64` (скрытие меню на
   мобильных) заменён на `left-[-16rem]` — Tailwind v4 не гарантированно генерировал первый.
4. **Аналитика** (`/analytics`) — индекс продуктивности (SVG-кольцо), 5 карточек метрик, график
   с переключением показателя и tooltip, донат-диаграмма задач, прогресс проектов, соблюдение
   сроков, фокус-время + heatmap по часам, heatmap активности за месяц, цели, достижения,
   персональные выводы, итог недели с модалкой плана. Все графики — ручной SVG/CSS, без новых
   зависимостей (библиотеки графиков в проекте нет). Новые файлы: `types/analytics.ts`,
   `lib/analytics-mock-data.ts`, `components/analytics/*`.
5. **Настройки** (`/settings`) — 12 категорий, единая модель `draft`/`saved` с индикатором
   несохранённых изменений, `Сохранить`/`Отменить`, персистентность в `localStorage`
   (`planly:settings`), предупреждение при закрытии вкладки с несохранёнными изменениями.
   Новые файлы: `types/settings.ts`, `lib/settings-defaults.ts`, `lib/settings-form-styles.ts`,
   `components/ui/Switch.tsx` (новый переключатель — единственный новый UI-примитив за всю
   сессию), `components/settings/*`.
   - **`useTheme.tsx` расширен аддитивно**: добавлены `themePreference` (`light`/`dark`/`system`)
     и `setThemePreference`. При старте `ThemeProvider` читает `planly:settings.appearance.theme`
     из `localStorage` — выбор темы в Настройках применяется ко **всему** приложению и переживает
     перезагрузку, не только на странице `/settings`. Существующий `toggleTheme` (использует
     Sidebar/Header) не менялся.
   - `Sidebar.tsx`: у всех пунктов (`Заметки`, `Напоминания`, `Аналитика`, `Настройки`) теперь
     реальные `href`, активная подсветка работает по `pathname`.

Ни один из этих файлов не закоммичен — весь список см. в `git status`.

## 4. Незавершённые задачи

- **Отправка писем не настроена.** Без `RESEND_API_KEY` ссылки подтверждения и восстановления
  только пишутся в лог бэкенда. Пока ключа нет, `REQUIRE_EMAIL_VERIFICATION` должен оставаться
  `false`, иначе после регистрации никто не сможет войти.
- **Данные из Supabase не перенесены.** Новая схема пустая; старые `profiles`/`tasks` остались в
  проекте Supabase. Перенос — отдельная задача (см. `docs/supabase-data-migration-plan.md` и
  `database/legacy-supabase/`).
- **Тесты бэкенда не ходят в базу.** Покрыты сессии, пароли, схемы валидации и то, что решается
  до Postgres (401/400/404, заголовки). Сами SQL-запросы проверены только вручную, интеграционных
  тестов с реальной базой нет.
- **`docs/ARCHITECTURE.md` и `docs/MODULES.md` устарели** — до сих пор написано «Notes /
  Reminders / Analytics / Settings — не реализованы». Не обновлял в рамках этой сессии (не
  входило в текущий запрос). Требуют ревизии в следующей сессии.
- **`docs/CURRENT_TASK.md`** — пуст («Нет активной задачи»), актуально, менять не требовалось.
- **Ничего не закоммичено.** Ветка `main` стоит на `b36b7d5 Merge remote main`; все изменения
  (доработки Dashboard/Calendar из прошлых сессий + 5 новых разделов) — только в рабочем дереве.
- **Reminders/Notes/Projects без `localStorage`** — осознанное решение по ТЗ каждой задачи
  («UI-скелет»), но из-за этого данные сбрасываются при перезагрузке страницы, в отличие от
  Dashboard/Calendar/Settings.
- **Reminders изолированы от `CalendarEntry`/`useTasksStore`** — напоминания не отображаются на
  реальной странице `/calendar` и не связаны с настоящими задачами, только с мок-данными внутри
  собственной страницы.
- **`Settings` пока не влияет на поведение других модулей** — например, `defaultPriority`/
  `defaultCategory` из категории «Задачи и проекты» сохраняются, но не подставляются при
  создании новой задачи в Dashboard; `accent`-цвет сохраняется, но не перекрашивает акценты
  в остальном приложении (только тема — `light`/`dark`/`system` — реально применяется глобально).
- Разово наблюдалось benign-предупреждение о рассинхронизации гидратации на `/reminders`
  (моковое время считается от `now`, различается на несколько секунд между сервером и клиентом
  при первом рендере) — не влияет на работу страницы, но при желании можно вынести вычисление
  моковых времён строго на клиент.

3. **Довести Projects и Notes до persistence** — добавить им `localStorage` (по образцу
   `useTasksStore`/`useCalendarStore`) или собственные Provider-сторы, чтобы данные не терялись
   при перезагрузке — логичное продолжение статуса «UI-скелет».

   `defaultCategory`/`defaultDuration` из «Задачи и проекты» должны влиять на создание новой
   задачи; `accent`-цвет из «Внешний вид» — реально перекрашивать акценты, а не только
   сохраняться.
5. **Согласовать стратегию коммитов с пользователем** — весь объём работы (доработки Dashboard/
   Calendar + 5 новых разделов) не закоммичен ни разу; нужно решить одним коммитом или по
   модулям, прежде чем начинать что-то новое поверх текущего рабочего дерева.
