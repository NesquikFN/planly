# 05. AI — Planly

Документ описывает архитектурные принципы AI-функций Planly. Конкретный провайдер модели и SDK выбираются на этапе реализации (Phase 3, см. [02-ROADMAP.md](02-ROADMAP.md)), здесь фиксируется подход, а не реализация.

## 1. Роль AI в продукте

AI в Planly — **ассистент, а не автопилот**. Он:

- помогает планировать и приоритизировать;
- резюмирует заметки и проекты;
- отвечает на вопросы в контексте данных пользователя;

но не совершает необратимых действий (удаление, массовое изменение) без явного подтверждения пользователя.

## 2. Ключевые сценарии использования

| Сценарий | Модуль | Описание |
|---|---|---|
| Резюме заметки/проекта | Notes / Projects | Краткая выжимка длинного контента |
| Приоритизация задач | Tasks | Рекомендации, что делать в первую очередь, с учётом дедлайнов |
| AI-чат с контекстом | AI | Диалог, который видит задачи/заметки/проекты пользователя |
| Разбор заметки на задачи | Notes → Tasks | Извлечение action items из свободного текста |
| Умное планирование дня | Dashboard / Calendar | Предложение расписания на основе задач и событий |

## 3. Архитектурные слои

- `src/services/` — интеграция с внешним AI-провайдером (запросы, стриминг ответов, обработка ошибок).
- `src/lib/` — построение промптов, форматирование контекста, ограничение размера контекста.
- `src/components/ai/` — UI-слой: чат, предложения, инлайн-подсказки.
- `src/hooks/` — состояние AI-взаимодействия на уровне React (загрузка, стриминг, история).

AI-логика не встраивается напрямую в компоненты — компоненты обращаются к хукам/сервисам, а не к провайдеру напрямую.

## 4. Контекст и данные

- В промпт передаётся только тот контекст пространства пользователя, который релевантен запросу (см. Phase 3 в roadmap) — не вся база данных целиком.
- История диалогов хранится в `AIConversation`/`AIMessage` (см. [04-DATABASE.md](04-DATABASE.md)) для возможности вернуться к разговору.
- Пользовательские данные не используются для дообучения сторонних моделей без явного согласия пользователя.

## 5. Приватность и безопасность

- AI-функции опциональны — пользователь может отключить отправку данных во внешнюю модель.
- Чувствительные поля (если появятся в будущем) исключаются из промптов по умолчанию.
- Ключи и доступ к AI-провайдеру хранятся только на серверной стороне, никогда не экспонируются в клиентском коде.

## 6. Постепенное расширение

1. **v1** — резюмирование и простые рекомендации (Phase 3).
2. **v2** — AI-чат с полным контекстом рабочего пространства.
3. **v3** — проактивные предложения и автоматизация (Phase 5).

Каждый уровень строится так, чтобы не требовать переписывания предыдущего.
