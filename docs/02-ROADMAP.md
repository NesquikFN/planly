# 02. Roadmap — Planly

Дорожная карта рассчитана на многолетнее развитие продукта. Фазы не привязаны к жёстким датам — переход к следующей фазе происходит по готовности, а не по календарю.

## Phase 0 — Фундамент (текущая фаза)

Цель: подготовить архитектуру и документацию до написания функционального кода.

- [x] Структура каталогов `src/`
- [x] Базовая документация (`docs/01`–`docs/06`)
- [ ] Выбор технологического стека (framework, БД, стилизация)
- [ ] Настройка линтинга, форматирования, CI

## Phase 1 — MVP

Цель: минимальный работающий продукт для личного использования.

- [ ] Аутентификация пользователя
- [ ] Модуль **Tasks**: создание, редактирование, статусы, дедлайны
- [ ] Модуль **Notes**: создание, редактирование, базовый поиск
- [ ] Простой **Dashboard**: сегодняшние задачи + последние заметки
- [ ] Базовая навигация и layout (см. [06-COMPONENTS.md](06-COMPONENTS.md))

## Phase 2 — Связность данных

Цель: связать модули между собой, превратить набор фич в единую систему.

- [ ] Модуль **Projects**: группировка задач и заметок
- [ ] Модуль **Calendar**: события + автоотображение дедлайнов задач
- [ ] Связи между заметками, задачами и проектами
- [ ] Полнотекстовый поиск по всем модулям

## Phase 3 — AI-ассистент (v1)

Цель: первая версия AI-функций (см. [05-AI.md](05-AI.md)).

- [ ] AI-резюмирование заметок и проектов
- [ ] AI-рекомендации по приоритизации задач
- [ ] AI-чат с контекстом текущего пространства пользователя

## Phase 4 — Командная работа

Цель: расширение с личного инструмента до небольших команд.

- [ ] Общие проекты и задачи между несколькими пользователями
- [ ] Роли и права доступа
- [ ] Уведомления и активность по проекту

## Phase 5 — Масштабирование и экосистема

Цель: продукт, готовый к росту на годы вперёд.

- [ ] Публичное API и вебхуки
- [ ] Интеграции с внешними календарями/таск-трекерами
- [ ] Мобильные клиенты
- [ ] AI-автоматизация (проактивные предложения, авто-планирование)

## Принципы приоритизации

1. Сначала связность данных, потом объём фич.
2. AI-функции строятся поверх стабильной модели данных, не наоборот.
3. Любая фича, ломающая архитектуру расширяемости, откладывается до пересмотра.
