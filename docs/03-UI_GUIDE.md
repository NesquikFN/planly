# 03. UI Guide — Planly

Руководство описывает визуальный язык и UX-принципы Planly. Цель — единообразный интерфейс, который не расползётся при добавлении новых модулей на протяжении многих лет разработки.

## 1. Принципы дизайна

1. **Ясность важнее плотности** — лучше меньше данных на экране, но понятных.
2. **Единообразие модулей** — Tasks, Notes, Projects, Calendar используют одни и те же паттерны карточек, списков, форм.
3. **Предсказуемость** — одинаковые действия выглядят и ведут себя одинаково во всех модулях.
4. **Спокойный визуальный тон** — инструмент для фокуса и планирования, не перегруженный анимациями и цветом.

## 2. Темизация

- Поддержка светлой и тёмной темы обязательна с самого начала.
- Все цвета определяются через переменные темы (design tokens), а не хардкодятся в компонентах.
- Токены темы живут в `src/styles/`.

## 3. Design tokens (структура, без конкретных значений)

- **Цвет**: base (фон/поверхности), text (основной/вторичный/приглушённый), accent (основной акцент бренда), semantic (success / warning / danger / info).
- **Типографика**: шкала размеров (display, heading, body, caption), один основной шрифт для UI.
- **Отступы (spacing)**: единая шкала (например, кратная 4px), используется во всех компонентах.
- **Радиусы и тени**: ограниченный набор значений, переиспользуемый во всех модулях.

## 4. Layout-структура

- **Layout** (`src/components/layout/`) — глобальная оболочка: навигация, сайдбар, шапка, области контента.
- Каждый модуль (`dashboard`, `tasks`, `notes`, `projects`, `calendar`, `ai`) встраивается в общий layout, не переопределяя его структуру.
- Адаптивность: desktop-first с обязательной поддержкой планшетных и мобильных размеров.

## 5. UI-примитивы (`src/components/ui/`)

Базовые переиспользуемые примитивы, не зависящие от бизнес-логики: кнопки, поля ввода, чекбоксы, диалоги, тултипы, бейджи, карточки, меню.

Правило: примитив из `ui/` не должен ничего знать о задачах, заметках или проектах — только о своём визуальном/интерактивном поведении.

## 6. Модульные компоненты

Компоненты в `dashboard/`, `tasks/`, `notes/`, `projects/`, `calendar/`, `ai/` строятся поверх примитивов `ui/` и не дублируют их логику. Подробнее — в [06-COMPONENTS.md](06-COMPONENTS.md).

## 7. Доступность (accessibility)

- Контраст текста и фона соответствует минимум WCAG AA.
- Все интерактивные элементы доступны с клавиатуры.
- Формы и диалоги используют корректную семантику и aria-атрибуты.

## 8. Состояния интерфейса

Каждый модуль обязан продумывать четыре состояния для списков и карточек:

- **Loading** — скелетоны, без резких скачков layout.
- **Empty** — понятное объяснение и предложение действия (например, "Создать первую задачу").
- **Error** — понятное сообщение и, где возможно, повтор действия.
- **Populated** — обычное состояние с данными.
